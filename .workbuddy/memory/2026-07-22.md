### PyInstaller 隔离子进程崩溃问题与解决
- 问题：PyInstaller 6.21.0 在 Windows 上 `SubprocessDiedError` — `collect_submodules()` 调用隔离子进程时子进程 exit code 1
- 在 Python 3.13（managed）和 Python 3.12（system + venv）上均复现
- 根因推测：Windows 环境变化（系统更新/安全策略）导致 STARTUPINFO handle_list 继承失败

**解决方案**（monkey-patch `build_exe.py`）：
```python
from PyInstaller import isolated as _iso_mod
import PyInstaller.isolated._parent as _iso_parent

class _FakeIsolated:
    def __enter__(self): return self
    def __exit__(self, *args): return False
    def call(self, function, *args, **kwargs):
        return function(*args, **kwargs)

_iso_parent.Python = _FakeIsolated
_iso_parent.call = lambda fn, *a, **kw: fn(*a, **kw)
_iso_mod.Python = _FakeIsolated
_iso_mod.call = lambda fn, *a, **kw: fn(*a, **kw)
```
- 关键：必须**同时** patch `_iso_parent` 和 `_iso_mod`（`from ._parent import Python, call` 在 import 时已绑定引用到 `isolated.__init__` 命名空间）
- patch 后 `collect_submodules` / `is_package` / `_collect_submodules` 在主进程直接执行

### 构建配置调整
- `excludes` 加 `"websockets"`（Python 3.13 兼容性问题 + 不需要 WebSocket）
- `main.py` 的 `uvicorn.run()` 加 `ws="none"`（不加载 websocket 协议）
- 使用系统 Python 3.12（`D:/programs/Python/python.exe`）打包

## DS Pro 调用失败根因找到并修复（12:23，用户反馈版本 v5.2.6）

**用户反馈**：
- WorkBuddy 版本 v5.2.6（比已知 bug v4.24.1 新，不是那个老 bug）
- 积分不变报错 → 说明**真失败**，没静默 fallback 到内置模型

**根因**（查腾讯云开发者社区确认）：
`models.json` 里有条目用 `id: "deepseek-v4-pro"` 和 `id: "deepseek-v4-flash"`，**和 WorkBuddy 内置模型 id 完全重名** → 触发"重复加载+鉴权冲突" → 调用失败。

**附加问题**：重名条目 `vendor` 写 `"DeepSeek"`，WorkBuddy 以为走内置厂商通道，但 url/apiKey 是用户自定义的 → 路由错乱。

**修复**（已重写 `~/.workbuddy/models.json`）：
- 所有自定义模型 id 改成独一无二的名字（加后缀）
- vendor 从 "DeepSeek" 改成 "OpenAI"（DeepSeek 接口是 OpenAI 兼容，vendor 写 OpenAI 即可）

**新 4 个条目**：
1. `glm-5.2` / GLM-5.2 (百炼) / vendor: Custom
2. `ds-v4-flash-official` / DeepSeek-V4 Flash (官方直连) / vendor: OpenAI
3. `ds-v4-pro-official` / DeepSeek-V4 Pro (官方直连) / vendor: OpenAI
4. `ds-v4-pro-bailian` / DeepSeek-V4 Pro (百炼) / vendor: Custom

**重要教训**：WorkBuddy models.json 中自定义模型的 `id` 字段**绝不能和内置模型 id 重名**（`deepseek-v4-pro`/`deepseek-v4-flash`/`glm-5.2` 等都是内置 id）。重名 → 鉴权冲突 → 调用失败。GLM-5.2 因为百炼先上、WorkBuddy 内置没有同名条目所以没冲突；DeepSeek 重名了所以出问题。

## zip 格式 bug 修复（18:30）

### 根因
- 之前用 `tar -caf xxx.zip` 命令打包
- tar 的 `-a`（auto-compress）按扩展名选格式，但 tar **不能真正生成 zip**
- 实际生成的是 POSIX tar archive，只是改了后缀为 .zip
- Windows 自带 zip 解压器打不开 tar 格式 → 审计员报错"压缩文件夹无效"

### 修复
- 改用 PowerShell `Compress-Archive` 生成真正的 zip
- 验证：`file` 命令显示 "Zip archive data, compression method=deflate"
- 文件头 `PK` (50 4B)，是标准 zip
- 大小从 110MB（tar 假 zip）→ 57MB（真 zip + deflate 压缩）
- 结构：`PBC-Agent-v5\PBC-Agent-v5.exe` + `PBC-Agent-v5\_internal\...`

### 教训
- 打 zip 必须用 `Compress-Archive`（PowerShell）或 `7z a -tzip`，不能用 `tar -caf`
- 验证 zip 真实性：`file xxx.zip` 应显示 "Zip archive data"，不是 "POSIX tar archive"
