## Qwen3.7-Plus 404 报错根因与修复（12:31）
用户重启后选 qwen3.7-plus 报错：
`404 The model 'qwen3.7-plus-bailian' does not exist or you do not have access to it.`
`错误码: custom-model-404`

**根因**（实测验证确认）：
WorkBuddy 把 models.json 里的 **`id` 字段直接当 model 参数传给 API**。我之前加后缀 `qwen3.7-plus-bailian` 是为了让 id 独一无二（避免和内置重名），但百炼只认真名 `qwen3.7-plus`，加了后缀就 404。

**验证脚本**：
- 百炼 + model="qwen3.7-plus-bailian" → ❌ 404 model_not_found
- 百炼 + model="qwen3.7-plus" → ✅ 成功

**修正之前的错误判断**：
之前以为"id 重名会冲突"是错的。WorkBuddy 实际机制是——**`id` 字段就是 API 的 model 参数**，必须用平台真名。避免和内置重名的正确方法不是改 id，而是：
1. **加 `useCustomProtocol: true`** ← 关键字段，告诉 WorkBuddy 走自定义协议（不和内置厂商通道冲突）
2. **`vendor` 写 "阿里云百炼"**（或 Custom）而不是 "Qwen"
3. **`maxTokens`** 字段（统一字段，不是 maxInputTokens+maxOutputTokens 分开写）

**已修复配置**（参考搜索结果中的标准写法）：
```json
{
  "id": "qwen3.7-plus",              ← 用真名，不加后缀
  "name": "Qwen3.7-Plus (百炼·多模态)",
  "vendor": "阿里云百炼",
  "url": "https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions",
  "apiKey": "sk-ec60...aa5",
  "useCustomProtocol": true,          ← 关键：避免和内置冲突
  "maxTokens": 65536,
  "supportsToolCall": true,
  "supportsImages": true,
  "supportsReasoning": true,
  "reasoning": {
    "supportedEfforts": ["minimal", "low", "medium", "high", "xhigh", "max"]
  }
}
```

**重要教训（修正之前的记忆）**：
WorkBuddy models.json 的 `id` 字段 = API 的 model 参数 = 必须用平台真实 model id。
- ❌ 错误做法：id 加后缀（如 `qwen3.7-plus-bailian`）→ 404
- ✅ 正确做法：id 用真名 + `useCustomProtocol: true` 避免和内置冲突

之前 DS Pro 的"id 重名冲突"判断可能也错了——DS Pro 失败真因可能只是 429 额度，不是 id 重名。但 DS Pro/Flash 的 id 用真名（deepseek-v4-pro/flash）是正确的，那个不用改。

## v7 打包（17:43-17:55）

### 第一次 build 卡住的原因
- build_exe.py 的 monkey-patch（disable PyInstaller isolated subprocess）在某些情况下损坏路径解析
- 表现：打印完参数后 pyi.run() 直接退出，不真正开始分析
- 之前 v6 能成是因为环境状态不同

### 解决方案
直接调 PyInstaller CLI（不用 build_exe.py）：
```
"D:/programs/Python/python.exe" -m PyInstaller app/main.py --name=PBC-Agent-v7 --onedir --noconsole --noconfirm \
  --distpath=D:/AgentProjects/IpoPBC/0 --workpath=D:/AgentProjects/IpoPBC/0/build \
  --specpath=D:/AgentProjects/IpoPBC/0/scripts \
  --hidden-import=app.api.routes_pbc ... (6 个 routes + 7 个 core/utils) \
  --add-data=D:/AgentProjects/IpoPBC/0/app/static;app/static ... (4 个 data) \
  --exclude-module=pytest ... \
  --collect-submodules=app
```
- **关键**：add-data 用绝对路径（相对路径会因 spec 在 scripts/ 子目录而错位）
- **关键**：补 `--hidden-import=app.api.routes_config`（v7 新增的 routes_config.py）

## CI 跑通里程碑（22:16）

### 失败 → 成功的迭代过程
1. v1 CI yml：用 `background: true` 字段（不是合法字段）+ bash -c → Windows runner 不支持
2. v2：改 Start-Process + pwsh，但 Python 输出中文 cp1252 编码炸 + $pid 是保留变量
3. v3：UTF-8 stdout + PYTHONIOENCODING + 变量名改 $svrPid，但 CI 干净环境无 demo 数据 → 7 个 FAIL
4. v4：setup_demo_data 自动准备数据，但调 _get 时还没定义 → NameError
5. v5：setup 调用挪到 _get 定义后，但 import 报 404（用错 Content-Type）
6. v6：multipart/form-data 正确上传 + sys.path.insert 修 import app
7. **22:16 CI 真过了**：16/16 全 PASS ✅

### 关键教训（写进 MEMORY）
1. Windows runner 默认编码 cp1252，print 中文必须 `sys.stdout.reconfigure(encoding='utf-8')` + 设 `PYTHONIOENCODING=utf-8` 环境变量
2. PowerShell 的 `$PID` 是保留变量不能赋值，用 `$svrPid` 或 `$serverProc`
3. 脚本在子目录（scripts/）里跑时 sys.path 不含项目根，要 `sys.path.insert(0, 项目根)`
4. FastAPI UploadFile = File(...) 要求 multipart/form-data，单一 Content-Type 直发 body 会 404
5. CI 干净环境没有 demo 数据，测试脚本必须自己 setup（生成数据 + 灌入）
