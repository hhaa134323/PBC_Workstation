## 输入路径策略调整（基于 OneDrive 实情）

从原方案「watchdog 主路径 + HTML5 拖拽兜底」调整为：

| 路径 | 角色 | 说明 |
|---|---|---|
| **HTML5 拖拽到浏览器** | **主路径** | File API 读本地路径，无网络传输，最适合 OneDrive |
| UI"重新扫描文件夹"按钮 | 兜底 1 | 后端 glob 扫描指定路径，用户手动触发 |
| watchdog 监听 | 兜底 2 | 仍保留，本地真实文件夹场景能触发，OneDrive 失败不报错 |

UI 主推拖拽（符合 OneDrive 用户从"此电脑"拖文件到浏览器的实际习惯）。

## Kimi-K3 百炼接入测试失败（15:14）
用户想用同一个百炼 key（sk-ec60...aa5）调 kimi-k3。

**测试结果**：全部失败（model_not_found）
- 通用域名 `https://dashscope.aliyuncs.com/compatible-mode/v1` + `kimi-k3` / `kimi-k3-turbo` / `kimi-k3.5` / `moonshot-v1-128k` → 全部 404

**根因（查百炼官方文档确认）**：
- GLM 系列可以用通用 dashscope 域名（所以之前配置成功）
- **Kimi 系列必须用业务空间专属域名**：`https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`
- WorkspaceId 在百炼控制台 → 业务空间详情页面查看
- 用户当前 key 没绑定业务空间/没提供 WorkspaceId → 无法测 kimi-k3

**结论**：同一个 key 理论上能调 kimi-k3（百炼文档说不需单独申请），但**需要先拿到 WorkspaceId 并用专属域名**。这是百炼平台对第三方模型（Kimi/智谱等）的接入策略：自研 Qwen 走通用域名，第三方模型走业务空间专属域名。

## 界面设计重大修订：按任务状态 tab 替代角色 tab（23:45）

用户指出"顶部 tab 切换 Staff/Senior/Manager 虽然对角色有把握，但分得不太好"。要求：**不提三种角色区分，但能满足这三种角色的需求**。

### 关键洞察

"切角色 tab"这个隐喻本身是错的：
1. 审计员不是固定身份（早上收料下午复核晚上汇报很常见）
2. 真实场景里没人会说"我现在切到 Senior 视角"
3. 三个角色不是三个独立工作流，是一条工作流的三个阶段
4. 小团队可能 2 人兼任多角色，"角色"概念尴尬

### 新方案：4 个任务状态 tab

- **Tab 1 待初检**（资料刚到，等人确认）→ 收料的人常驻
- **Tab 2 待复核**（已初检，等高级审计员复核）→ 复核的人常驻
- **Tab 3 超期未提供**（风险雷达识别的缺料项）→ 监督进度的人常驻
- **Tab 4 已完成**（终态归档）→ 所有人

### 设计原则

- 不提角色身份，用户只看"我有啥活要干"
- 一人兼多角色无障碍（早上 Tab 1、下午 Tab 2、晚上 Tab 3）
- 小团队友好（2 人兼任多角色完全无影响）
- 工作流连续（4 个 tab 是同一条链路的状态推进）
- AI 元素按状态自然分布（Tab 1 置信度+进度条+toast / Tab 2 AI 复核提示 / Tab 3 化解卡片+热力图）
