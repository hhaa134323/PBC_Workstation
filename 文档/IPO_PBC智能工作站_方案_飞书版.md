## 二、选题与痛点

**选题**：IPO 审计 PBC（Provided by Client，客户提供资料）智能管理工作站

**核心痛点**：初级审计员在 PBC 管理上高度依赖手工——收资料、分拣、命名、归档、更新 Excel 状态。环节重复、易错、跨人跨系统。

**SOP 依据**：公司已有《IPO 审计项目 PBC 完整性检查标准作业程序》（AUD-SOP-PBC-01 V1.0），明确定义了角色、流程、状态、异常处理。本产品是 SOP 的"AI 原生 + 双击即用"实现。

## 四、差异化定位（乔布斯式双重跳跃）

### 4.1 两轴矩阵

|  | 需配置/培训（左） | 双击即用（右） |
|---|---|---|
| **AI 原生（上）** | 通用审计 SaaS 平台 | **我们（目标，空白象限）** |
| **规则/手动（下）** | 纸质流程 | Excel 手工核对 |

**Melody 竞品位置**：中间偏下（规则为主 + 中易用）

### 4.2 双重跳跃策略

iPhone 式双重跳跃——同时跳两个维度：

- **上推智能化**：AI 原生（LLM 分类、AI 置信度标红、缺口模式识别、替代程序建议）
- **右推易用性**：双击即用（单一输入、零配置、按流程走）

**差异化不是"功能多"，是"两个维度都做到极端"。形态不是差异化核心，A+F 功能价值才是。**

### 4.3 差异化双支柱

- **支柱 A · 三角色协作工作台**：竞品只服务 Staff 单机分拣，我们服务整个审计团队（Staff/Senior/Manager 三视角）
- **支柱 F · 缺料风险雷达**：竞品把 PBC 当操作问题（收齐就完了），我们把 PBC 缺口当审计风险信号
- **环节 5 · 风险化解助手**：F 的行动层，基于缺口做影响分析+替代程序建议+升级汇报

## 五、基于 SOP 的产品思路

以"一份 PBC 资料的完整生命周期"为主线，5 环节贯穿。

### 5.1 五环节流程

| 环节 | 名称 | SOP 对应 | 差异化定位 |
|---|---|---|---|
| 1 | 客户共享文件夹（输入） | §5.1 资料接收 | 非差异化（地基） |
| 2 | AI 智能处理 | §5.1-5.5 | 地基 + **藏差异化（完整性检查）** |
| 3 | 三角色协作审阅 | §3 + §5.4 | **差异化支柱 A** |
| 4 | 缺料风险雷达 | §6 异常处理 | **差异化支柱 F** |
| 5 | 风险化解助手 | §6 替代程序 | F 的行动层（化解风险） |

**闭环**：环节 5 化解风险后，客户补料重新进入环节 1，形成自我循环。

### 5.2 环节 2 详解（AI 智能处理）

| 子功能 | SOP 条款 | 说明 |
|---|---|---|
| 识别归类 | §5.1 | 判断基础资料 vs 穿行测试证据，对照清单识别请求项 |
| **完整性检查** | §5.2 | **清单覆盖率 + 期间连续性（三年一期有无断档）** |
| 状态标记 | §5.3 | 自动回写 Excel 状态列 |
| 文件归档 | §5.5 | 命名（编号_描述_期间_版本.pdf）+ 目录 |

**关键差异化**：§5.2 的"期间连续性检查"是 AI 强项——读文件内容判断期间覆盖，Melody 完全没碰。本次做简单版（文件名/元数据判断）。

### 5.3 环节 3 详解（三角色协作审阅）

严格映射 SOP §3 角色职责。**界面设计**：不是 Staff页/Senior页/Manager页 三选一切换，而是**一个统一界面，信息区块按角色自然聚焦**——三角色看到同一套数据，但默认视线不同，谁都能看全貌。

**Staff（5 项职责）**：

1. 接收客户 PBC 资料
2. 执行初步完整性检查（清单覆盖率、基本格式、期间连续性）
3. Excel PBC 清单更新状态
4. 资料存入指定文件夹并建立超链接
5. 对"未提供/异常"项标记并初步跟进

**Senior（4 项职责）**：

1. 复核 Staff 的完整性检查结果
2. 确认资料满足底稿要求（签字盖章、版本正确性、数据勾稽、样本代表性）—— 4 维度复核
3. 批准状态更新为"已提供"
4. 解决复杂/争议性资料缺失，决定替代程序

**Manager/Partner（3 项职责）**：

1. 监督整体 PBC 进度
2. 协调重大资料缺失的客户高层沟通
3. 审批关键事项豁免/特殊处理

### 5.4 环节 4 详解（缺料风险雷达）

**SOP 依据**：§6 异常处理机制

- **超期阈值 = SOP 规定的"5 个工作日"**（非拍脑袋）
- SOP 原文："关键 PBC 超过 5 个工作日仍未提供，向 Senior 汇报"
- 我们的雷达 = §6 异常处理的自动化呈现 + 升级触发

**功能**：

- 超期自动识别（按 5 工作日阈值）
- 缺口模式反推审计风险热点（如存货科目迟迟收不齐 → 可能存货有问题）
- Manager 视角的项目风险热力图

### 5.5 环节 5 详解（风险化解助手）

**SOP 依据**：§6 异常处理（替代程序）+ §5.4 Senior 职责（决定替代程序）

**为什么不做催办**：催办针对客户、方式多样、每个项目不一样、无法统一化、AI 价值低。

**风险化解助手的三条化解路径**：

| 路径 | 说明 | 示例 |
|---|---|---|
| ① 影响分析 | 缺口→影响哪些审计科目/结论 | 存货盘点表缺失 → 影响存货科目期末余额审计结论 |
| ② **替代程序建议**（核心） | AI 基于资料类型+审计准则知识库，推荐替代审计程序 | 银行流水缺失 → 建议执行银行函证+检查对账单+核对网银 |
| ③ 升级汇报包 | 超阈值自动生成给 Senior/Manager 的结构化汇报 | 哪些超期、影响哪些科目、建议关注等级 |

**为什么比催办好**：SOP 依据强（§6）、可统一化（审计准则有标准）、AI 价值高（知识库+推理）、有审计深度、不依赖客户。**这是 AI 价值最高的环节**。

## 六、状态机设计（SOP §4.2 贯穿全工作台）

### 6.1 四状态定义

| 状态 | 颜色 | 定义 |
|---|---|---|
| 未提供 | 红色 | 截止日到未提供，或严重缺失 |
| 已提供，审核中 | 深绿 | 已收到并整理，等 Senior 复核 |
| 已提供 | 浅绿/灰 | 终态，Senior 复核通过，已归档 |
| 不适用 | 灰色 | 不涉及公司情况 |

### 6.2 状态流转

```
未提供 ──(Staff 初检)──→ 已提供，审核中
                              │
                  ┌───────────┴───────────┐
                  │                       │
            (Senior 通过)          (Senior 不通过)
                  │                       │
                  ▼                       ▼
              已提供              退回"未提供"

不适用（独立状态，需备注理由）
```

Excel 中通过条件格式自动着色，限制状态列只能输入这四个选项（数据验证）。

### 7.1 资料粒度区分（重要）

资料有两种粒度，需在数据模型中区分：

| 资料粒度 | 例子 | 矩阵呈现 |
|---|---|---|
| **公司级** | 子公司银行流水、某账套明细账 | 在"实体_年份"格打 Y/N |
| **集团级/合并级** | 合并明细账、集团章程、合并报表 | 不属于单一公司，单独归属 |

测试用 ABC 公司（3 家子公司 + 1 个集团合并），既简单又能覆盖两种粒度。

## 九、产品形态

**形态不是独立选择，是从"双击即用 + 无技术背景用户 + Windows + 最低成本"约束推导的结果。**

### 9.1 推导过程

| 约束 | 推导 |
|---|---|
| 必须双击即用 | 不能要用户装 Python/装依赖/配环境 |
| Windows 最低成本 | 打包成 .exe，双击运行，自带运行环境 |

### 9.2 形态选择

**打包成 exe 的本地应用**：HTML + FastAPI + PyInstaller

- **前端**：HTML + Alpine.js（单页 Web，三角色统一界面）
- **后端**：FastAPI 本地服务（127.0.0.1）
- **打包**：PyInstaller 打包成单 exe，用户双击即用
- **输入**：客户指定的共享文件夹（单一入口）
- **数据**：全程模拟数据，ABC 公司、覆盖全状态

## 十、技术架构（5 层）

| 层 | 内容 | 说明 |
|---|---|---|
| 第 1 层 · 用户层 | 双击 PBC工作站.exe → 自动打开浏览器 | 无需装 Python/依赖 |
| 第 2 层 · 前端层 | 单页 Web 应用（HTML/CSS/JS + Alpine.js） | 三角色统一界面，信息区块按角色聚焦 |
| 第 3 层 · 后端层 | FastAPI 本地服务（127.0.0.1） | API + 业务逻辑 + 文件操作 + Excel 读写 + 调度 AI |
| 第 4 层 · AI 能力层 | LLM API（百炼平台）+ 审计知识库 | 分类识别、完整性检查、置信度评估、替代程序建议 |
| 第 5 层 · 数据/文件层 | 共享文件夹 + PBC Excel + 归档目录 | 输入/状态/输出三处文件 |

### 10.1 AI Agent 核心逻辑（感知-思考-行动-人确认）

AI Agent 不是简单调 API，是"感知-思考-行动-人确认"的循环：

- **环节 2**：感知（扫描文件夹新文件）→ 思考（LLM 识别+匹配+期间检查+置信度）→ 行动（命名+归档+Excel回写）→ 人确认（Staff 确认/纠正）
- **环节 3**：感知（看所有"审核中"项+置信度）→ 思考（置信度<0.7 标红）→ 行动（Senior 复核区置顶红项）→ 人确认（Senior 通过/退回）
- **环节 5**：感知（风险雷达识别缺口）→ 思考（查知识库+推理替代程序）→ 行动（生成化解建议卡片）→ 人确认（Senior 采纳并记录底稿）

**关键：AI 不替代人判断，是帮人把"最该看的"挑出来。**

## 十三、数据流（一份资料的完整旅程）

```
客户把"银行流水.pdf"拖进共享文件夹
    ↓ watchdog 监听到新文件
后端读取文件 → pdfplumber 提取文字
    ↓
LLM 接收（文件内容 + PBC 清单）→ 输出匹配结果 + 置信度 + 期间检查
    ↓
后端自动命名 + 归档到/PBC/C_货币资金/ + openpyxl 回写 Excel 状态
    ↓
前端实时刷新 → Staff 看到新项（绿条"已提供审核中"）
    ↓
Senior 复核区看到（置信度0.92，标绿，优先级低）
    ↓
Senior 点"通过" → 状态改"已提供"（终态）
```

超期未收齐时：

```
风险雷达扫描 → 发现"存货盘点表超期7天"
    ↓
AI 查知识库 → 生成影响分析+替代程序建议
    ↓
Manager 监督区显示红警 + Senior 看到化解建议
    ↓
Senior 采纳替代程序 → 记录底稿
```
