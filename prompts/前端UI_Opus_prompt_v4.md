# 任务

为「IPO 审计 PBC 智能管理工作站」设计前端界面（单页 Web 应用），出 HTML + Alpine.js 完整样例代码。

# 产品定位（一句话）

IPO 审计 PBC（客户提供资料）智能管理工作站。
核心差异化：协作审阅工作流（支柱 A）+ 缺料风险雷达（支柱 F）+ AI 原生 + 双击即用。
形态：本地 FastAPI 服务（127.0.0.1:8000），单页 Web 应用，用户双击 exe 启动自动开浏览器。

# 5 环节流程（产品主线）

1. 客户共享文件夹（输入）— 用户配置 OneDrive 挂载路径，后端直接读本地路径（零上传）
2. AI 智能处理 — 自动分类识别、命名归档、Excel 回写状态、完整性检查（期间连续性）
3. 协作审阅 — 待初检 → 待复核 → 已完成（按任务状态 tab 自然聚焦，不提角色身份）
4. 缺料风险雷达 — 超期识别（SOP §6：超 5 工作日）+ 缺口反推风险热点
5. 风险化解助手 — 影响分析 + 替代程序建议 + 升级汇报包

# 状态机（4 状态 + 待定）

- 未提供（红色 #FFC7CE）— 截止日到未提供，或严重缺失
- 已提供，审核中（深绿 #C6EFCE）— 已收到整理，等复核
- 已提供（浅绿 #E2EFDA）— 终态，复核通过已归档
- 不适用（灰 #D9D9D9）— 不涉及公司情况
- 待定（不着色，归一化到未提供）

颜色符合中国审计习惯：红=未提供（缺料风险），绿=已提供（健康）。

# 界面核心设计：4 个任务状态 tab（不提角色）

**核心原则**：不强制用户切换"角色身份"（Staff/Senior/Manager），而是按"任务状态"自然聚焦——用户点哪个 tab 就看哪个状态的事项。审计员早上做收料、下午做复核、晚上做汇报时无切换认知负担。

类比 GitHub Issues：没有"Maintainer/Contributor 切换"，只有 Open/Closed tab。Linear/Notion 任务板：没有"Manager 切换"，只有 In Progress/Review/Done 状态列。

## 4 个 tab 设计

### Tab 1：待初检（资料刚到，等人确认）
- 顶部：扫描新文件大按钮 + AI 处理进度条（4 步：解析→分类→归档→回写）
- 主区：低置信度项标红置顶 + 置信度进度条 + AI toast 区
- 操作：标记初检完成 → 推到"待复核"
- 自然使用者：收资料的人（早上来收料的人常驻这个 tab）

### Tab 2：待复核（已初检，等高级审计员复核）
- 顶部：4 维度复核清单（签字盖章/版本正确性/数据勾稽/样本代表性）
- 主区：置信度低的项置顶（红色高亮提醒）+ 已有 AI 影响分析摘要
- 操作：通过 → 推到"已完成" / 退回 → 推回"待初检" + 触发风险化解
- 自然使用者：做复核的人（下午做复核的人常驻这个 tab）

### Tab 3：超期未提供（风险雷达识别的缺料项）
- 顶部：总体进度仪表盘（已收/待审/超期）
- 主区：风险热力图（实体×科目）+ 高风险项列表 + AI 影响分析
- 操作：点击高风险项 → 弹风险化解卡片 → 采纳替代程序 / 收升级汇报包一键复制
- 自然使用者：监督进度的人（晚上看进度的人常驻这个 tab）

### Tab 4：已完成（终态归档）
- 顶部：总体完成率
- 主区：已归档文件列表（按实体分组）+ 状态历史日志
- 操作：查看详情/撤销归档
- 自然使用者：所有人

# 5 个 AI 主动推送 toast 时机

按优先级分级：

| 级别 | 时机 | 推送内容 | 形态 |
|---|---|---|---|
| 🔴 高（常驻置顶） | 期间检查异常 | ⚠ "这份银行流水覆盖 2025/01-09，缺 10-12 月，建议退回客户补料" | 强制弹+常驻，需手动 dismiss |
| 🔴 高（常驻置顶） | 超期阈值 | ⚠ "存-4 存货盘点表已逾期 7 天，按 SOP §6 应向 Senior 汇报" | 强制弹+常驻 |
| 🟡 中（3 秒消失） | 置信度偏低 | "这份文件 AI 匹配置信度 0.58，原因：印章模糊。建议人工确认" | 弹 3 秒 |
| 🟡 中（3 秒消失） | 缺口模式识别 | "本周存货类资料缺料率 80%，可能存在客户拖延" | 弹 3 秒 |
| 🟢 低（静默记录） | 扫描完成 | "扫描完成，发现 N 份新文件，已自动分类归档" | 静默，可点开看 |

toast 可点击查看详情（跳到对应 item），可"采纳"/"忽略"。

# 界面关键要求

## 一、单页统一界面，按任务状态 tab 聚焦（不提角色）

4 个 tab（待初检/待复核/超期未提供/已完成）作为顶部主导航。用户点哪个 tab 就看哪个状态的事项。

**核心原则**：
- **不提"你是 Staff/Senior/Manager"**，用户只看"我有啥活要干"
- **一人兼多角色无障碍**：早上 Tab 1、下午 Tab 2、晚上 Tab 3 无切换负担
- **小团队友好**：2 人兼任多角色完全无影响
- **工作流连续**：4 个 tab 是同一条链路的状态推进，不是三个独立视角
- **AI 元素按状态自然分布**：Tab 1 有置信度+进度条+toast、Tab 2 有 AI 复核提示、Tab 3 有化解卡片+热力图——AI 元素不重复，按状态自然出现

## 二、输入区（环节 1，主路径是配置扫描，不是拖拽）

- **主路径**：顶部导航有"设置→选择客户文件夹"按钮，配置 OneDrive 路径
- Tab 1 待初检的主区主推"扫描新文件"大按钮
- 拖拽区作为兜底，>50MB 警告"建议改用扫描文件夹"
- 扫描后显示 4 步进度条 + 当前正在处理的文件名

## 三、PBC 清单主表（Tab 1/2/3 共用，按状态过滤）

长表展示，列：
- 资料编号 / 一级分类 / 相关科目 / 资料名称 / 实体归属 / 状态（带颜色徽章） / 置信度（带进度条，<0.7 标红） / 逾期天数 / 文件路径 / 操作

操作列按当前 tab 不同显示不同按钮：
- Tab 1 待初检：标记初检完成 / 跟进
- Tab 2 待复核：通过 / 退回 / 看 4 维度复核清单
- Tab 3 超期未提供：升级 / 看影响分析
- Tab 4 已完成：查看详情/撤销归档

支持过滤：
- 按实体（集团合并/ABC科技/ABC制造/ABC商贸）
- 按一级分类（18 类）
- 按风险等级（high/medium/low/none）
- 按逾期天数（>30 / >100）

支持矩阵视图切换：实体 × 报告期间 矩阵（Y/N 单元格，点击钻取）

## 四、Tab 3 风险雷达（缺料风险雷达，所有 tab 可见但 Tab 3 主区域）

- 仪表盘顶部：总体进度（已收齐 X / 待审 Y / 超期 Z）
- 风险热力图：按一级分类 × 实体，单元格颜色按超期天数渐变（绿→黄→红）
- 高风险项列表：超期 > 100 天的 27 项，按风险等级排序，每项显示：资料编号 / 名称 / 逾期天数 / 影响科目 / AI 影响分析摘要

## 五、风险化解助手（环节 5）

点击高风险项 → 弹出化解卡片，三块内容：
1. **影响分析**（带"AI 生成/知识库兜底"小标签）：缺这份资料会影响哪些审计科目/结论
2. **替代程序建议**（核心，带小标签）：AI 推荐替代审计程序，每条带"采纳"按钮
3. **升级汇报包**：结构化汇报文本，**一键复制按钮**

## 六、AI 元素体现（差异化）

- 顶部 toast 区（AI 主动推送，5 个时机）
- 每条数据带 AI 置信度进度条（<0.7 红色高亮提醒复核）
- 处理进度可视化（4 步：解析 → 分类 → 命名 → 回写）
- AI 处理历史记录抽屉（点击查看每次 AI 处理的 prompt + response + 模型）
- 替代程序建议卡片（带"AI 生成 / 知识库兜底"小标签区分来源）

## 七、首启引导页（Onboarding）

首启检测 user_config 不存在 → 弹 3 步引导：
1. 欢迎（"欢迎使用 PBC 智能管理工作站"）
2. 选择客户共享文件夹（配置 OneDrive 路径）
3. 演示数据预加载（提示"已加载 103 项 PBC 清单 + 20 个模拟文件，可立即体验"）

类比：VS Code 首次启动 / Slack 加入工作区。

# 后端 API 接口（前端调这些）

## 配置接口（首启用）
- `GET /api/files/config/folder` → 返回当前客户文件夹路径 + is_default + file_count + OneDrive 提示
- `POST /api/files/config/folder` → 保存客户文件夹路径（body: `{client_folder: "..."}`）

## PBC 清单
- `GET /api/pbc/list?status=未提供&entity=ABC科技&risk=high&overdue_min=30` → `{count, items: [...]}`
- `GET /api/pbc/{item_id}` → 单条详情
- `PUT /api/pbc/{item_id}/status` → body `{status, changed_by, note}` → 更新状态

## 文件处理
- `POST /api/files/scan-folder` → 触发扫描，返回 `{task_id, status: "processing", files: [...]}`
- `GET /api/files/task/{task_id}` → 查询任务状态（progress + results）
- `GET /api/files/recent-tasks?limit=20` → 最近任务列表
- `POST /api/files/drag-drop` → 兜底拖拽上传（>50MB 警告用扫描代替）
- `POST /api/files/drag-drop/check` → 拖拽前检查文件大小

## 风险雷达
- `GET /api/risk/dashboard` → overall_progress + overdue_summary + overdue_items + risk_heatmap + audit_risk_hotspots
- `GET /api/risk/heatmap` → entities + categories + cells + legend
- `GET /api/risk/resolve/{item_id}` → impact_analysis + alternative_procedures + escalation_report（含 used_fallback 标识）
- `GET /api/risk/escalation` → 整体升级汇报包（summary + items_by_priority + report_text）

## 健康检查
- `GET /health` → `{status: "ok", version: "0.1.0"}`
- `GET /` → 返回 index.html

# 技术约束

- Alpine.js（CDN 引入，不需要 build step）
- 原生 HTML + Tailwind CSS（CDN）
- 单页应用，所有视图在一个 index.html
- 中文界面，中文审计术语
- 现代简洁专业风格，参考 Linear / Notion / Vercel 设计语言
- 浅色主题为主（白底+深色文字，避免深色背景）
- 中文涨跌色：红=未提供（缺料风险），绿=已提供（健康）
- 路径用相对路径引用 `/static/css/style.css` 和 `/static/js/app.js`
