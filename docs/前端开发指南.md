### 数据流
```
后端 API → Alpine data (this.xxx) → x-html / x-text 渲染
                ↑
  pbc-enhance.js 通过 root() 拿到 Alpine data 引用
  可以读写 Alpine 的响应式数据
```

### 关键约束：pbc-enhance.js 的特殊性

`pbc-enhance.js` 不在 Alpine 的 x-data 作用域内，它通过 `root()` 函数从外部访问 Alpine 数据。这带来以下限制：

- **不能在函数内部声明会被外部函数引用的变量**。之前 `var currentTab = 'client'` 声明在 `build()` 内部，但 `visible()` 函数引用了它 → ReferenceError → render 崩溃 → Promise.then 吞掉异常 → 列表永远卡在 loading。**所有跨函数共享的变量必须在 IIFE 顶层声明**。

- **不能假设 Alpine data 已就绪**。`root()` 可能返回 null（页面还没加载完），所有访问 `d.xxx` 的地方都要判空。

- **不能假设 Alpine data 不会变**。Alpine 的响应式数据可能在任何异步点更新，读取后立即用，不要缓存。

## 2. 已知 Bug 模式（必须避免）

### 2.1 变量作用域泄漏
```javascript
// ❌ 错误：currentTab 在 build() 内声明，visible() 引用时 ReferenceError
function build() {
  var currentTab = 'client';  // ← 函数作用域，外面看不到
}
function visible() {
  if (currentTab === 'client') ...  // ← ReferenceError!
}

// ✅ 正确：在 IIFE 顶层声明
var currentTab = 'client';
function build() { ... }
function visible() { if (currentTab === 'client') ... }
```

### 2.2 异步操作后不更新 UI
```javascript
// ❌ 错误：点击按钮只调异步函数，不立即更新 UI
btn.addEventListener('click', function() {
  d.startScan();  // 异步，Alpine 要等下一 tick 才更新
  // 按钮文字要等下次 load() 才刷新
});

// ✅ 正确：立即更新 UI + 轮询状态
btn.addEventListener('click', function() {
  btn.textContent = '整理中...';
  btn.disabled = true;
  Promise.resolve(d.startScan()).catch(()=>{});
  var n = 0;
  var poll = setInterval(function() {
    if (d.scan && d.scan.active || n > 10) {
      clearInterval(poll);
      load(true);  // 刷新数据
    }
    n++;
  }, 300);
});
```

### 2.3 文件过滤不完整
客户共享文件夹里的非真实文件必须过滤：
```javascript
// 必须过滤的文件名模式
if (name.startsWith('.') || name.startsWith('~$') ||
    name === 'Thumbs.db' || name === 'desktop.ini' || name === '.DS_Store') {
  continue;  // 跳过
}
```
- `~$xxx.xlsx` — Excel 打开时创建的锁文件，关闭后自动删除
- `.xxx` — 隐藏文件
- `Thumbs.db` / `desktop.ini` — Windows 系统文件

### 2.4 字段名不匹配
```python
# archive_file() 返回 {"archived_path": "..."}
# archive_directory() 返回 {"archived_dir": "..."}
# 取值时必须兼容两种 key：
path = result.get("archived_path") or result.get("archived_dir", "")
```

### 2.5 状态过滤不一致
```javascript
// ❌ 错误：用 status（原始值）而不是 status_normalized（标准化值）
const overdue = items.filter(i => i.status === '未提供' && i.overdue_days > 0);

// ✅ 正确：用 status_normalized
const overdue = items.filter(i =>
  (i.status_normalized || i.status) === '未提供' && i.overdue_days > 0
);

// ✅ 更好：显式排除已完成的
const isProvided = ['已提供', '不适用', '已提供，审核中'].includes(s);
return !isProvided && overdue > 0;
```

## 3. 日期处理

### Excel 日期解析
`_parse_date()` 会把 Excel 单元格值转成 `datetime.date` 对象。后续代码如果要用这个值做日期计算，**必须处理 `date` 类型**：

```python
# ❌ 错误：只处理 str 和 int，date 对象走 else → eb_date=None → 计算跳过
if isinstance(eb, str):
    eb_date = datetime.fromisoformat(eb).date()
elif isinstance(eb, (int, float)):
    eb_date = (base + timedelta(days=int(eb))).date()
else:
    eb_date = None  # ← date 对象走到这里

# ✅ 正确：加 date 类型分支
if isinstance(eb, date):
    eb_date = eb  # 已经是 date 对象
elif isinstance(eb, str):
    eb_date = datetime.fromisoformat(eb).date()
elif isinstance(eb, (int, float)):
    eb_date = (base + timedelta(days=int(eb))).date()
```

### 逾期天数实时计算
`overdue_days` 在 Excel 里是写死的旧值，`read_pbc_list` 会实时覆盖（用 `today - expected_by`）。但只在状态不是"已提供/不适用"时才覆盖——已归档项的 `overdue_days` 保留旧值，热力图和仪表盘必须额外过滤这些项。

## 4. 数据源同步点

每个操作可能涉及多个数据源，必须全部更新：

| 操作 | manifest | pending_confirm | file_archive | PBC Excel | change_log |
|------|----------|-----------------|--------------|-----------|------------|
| scan | →pending | — | — | — | →added |
| confirm_archive(文件) | →processed | →confirmed=1 | 新增 | →file_path | →archived |
| confirm_archive(目录) | 子文件→processed | →confirmed=1 | 新增 | →file_path(archived_dir) | →archived |
| reclassify | 旧删新processed | — | 旧删新加 | 旧清新填 | →reclassified |
| skip | →processed | →confirmed=2 | — | — | — |

**关键**：目录归档（穿行测试、年度文件夹）的 `archive_directory()` 返回 `archived_dir` 不是 `archived_path`。取值时必须兼容。

## 5. 测试要求

- 每个新功能或 bug 修复都要写测试

## 6. 前端模块化建议

如果要做前端重构，建议方向：
1. 把 `pbc-enhance.js` 的逻辑合并回 `index.html` 的 Alpine 组件里
2. 或抽成正式的 Alpine component/directive
3. 消除 `root()` 这种从外部扒 Alpine 内部引用的模式
4. 让数据和渲染在同一个作用域内，靠 Alpine 的响应式自动更新
