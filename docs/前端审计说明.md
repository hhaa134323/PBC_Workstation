# 前端审计说明

这份文档记录一次前端排障的结论。核心结论是: **现有测试全绿, 但它们测不到前端。**

## 一、为什么坏了一整天却没有测试拦住

### scripts/test_hitl_full_flow.py

文件头写的是 HITL 完整业务流程测试 (Playwright 交互式), 共 11 步。实际通读之后, `page` 对象只做三件事:

- `page.goto(BASE)`
- `page.screenshot()`
- `page.evaluate()` 直接往 `el._x_dataStack[0]` 塞变量

**零次真实点击。** 所有业务动作都是 urllib 直连后端:

| 步骤 | 声称的动作 | 实际做的事 |
| --- | --- | --- |
| 1 | 新建项目 | `urllib POST /api/projects/create` |
| 2 | 导入清单 | `urllib POST /api/pbc/{pid}/import` |
| 4 | 扫描文件夹 | `urllib POST /api/files/{pid}/scan-folder` |
| 5 | 切到待归档 tab | `page.evaluate(switchTab)` + 截图, 断言的是 urllib 拿到的数据 |
| 6 | 确认归档 | `urllib POST /api/files/{pid}/confirm/{cid}` |
| 7 | 跳过 | `urllib POST /api/files/{pid}/skip-confirm/{cid}` |
| 8 | 改分类 | `urllib POST /api/files/{pid}/reclassify-confirm/{cid}` |
| 9 | 批量归档 | `urllib POST /api/files/{pid}/batch-confirm` |
| 11 | 变更面板 | `urllib GET /api/files/{pid}/change-log?limit=10` |

步骤 5 最致命: 断言 `len(items) > 0` 断的是 urllib 拿到的后端数据, 跟这个 tab 有没有渲染出来毫无关系。待确认 tab 全白也照样 PASS。

**11 项全绿只能证明后端是好的, 前端一个字都没测。**

脚本自身还有三个 bug:

1. `BASE = 'http://127.0.0.1:8111'`, 和实际启动端口 8000 不一致, 直接跑会全部连接失败
2. 绝对路径硬编码 `D:\AgentProjects\IpoPBC\0\...`
3. 步骤 4 轮询走的是 `/api/files/task/{task_id}` (legacy 路由, 不带 project_id), 而前端实际调的是 `/api/files/{pid}/task/{tid}`。**前端真正走的轮询路由从来没被测过**, 而这正是 scan-folder 三种无 task 返回会打成 `/task/undefined` 的地方

### scripts/regression_v7.py

`t_frontend_has_v7_funcs()` 只做 `'fileZone' in html` 这类纯字符串包含检查, 不执行 JS, 不启动 Alpine, 不渲染 DOM。即使 JS 语法错误导致 `pbcApp()` 完全起不来, 28/28 依然全绿。

**回归 28/28 全通过在前端这件事上零信息量。**

## 二、替代方案

新增 `scripts/smoke_frontend.py`, 真驱动浏览器:

- `page.on('pageerror')` 抓所有 JS 运行时异常
- `page.on('console')` 抓 console.error
- `page.on('requestfailed')` 抓网络失败, 包括 CDN 挂掉
- `page.on('response')` 抓所有 4xx / 5xx
- 用 `el._x_dataStack[0]` 是否存在判断 Alpine **真的初始化了**, 而不是字符串检查
- `document.body.innerText.trim().length > 200` 判断是否白屏
- 遍历点击每个 tab, 比对点击前后的错误数组增量
- 环境变量 `PBC_TEST_BASE` (默认 8000) 和 `PBC_TEST_PROJECT` (默认 demo), 不硬编码路径

跑法见脚本头部注释。Alpine 起不来时会把全部 JS 报错打出来并 `sys.exit(1)`。

## 三、待修清单

### 3.1 HITL 默认开着, 前端没有收件箱

`routes_files.py` 里 `_hitl_on = bool((_raw.get('ai_flags') or {}).get('hitl_mode', True))`, **默认 True**。也就是说扫描出来的文件默认全部进 `pending_confirm` 表等人确认, 不会自动归档。

但 SPEC.md 明确写着未完成项: **前端待确认 tab + 确认 / 改分类 / 跳过按钮**。

后果: 用户扫描完文件, 什么都看不到, 以为扫描坏了。实际是文件全躺在待确认队列里, 前端没有界面去取。

两条路:

- 短期把 `ai_flags.hitl_mode` 置为 false, 恢复自动归档, 先让流程能跑通
- 正解是把待确认 tab 补上, 调 `GET /api/files/{pid}/pending-confirm`, 拿 `items` 渲染, 每行接 `confirm` / `skip-confirm` / `reclassify-confirm` 三个按钮

### 3.2 scan-folder 有四条出口, 前端只处理了一条

`scan_folder_by_project` 的返回分四种:

| status | 有 task_id 吗 |
| --- | --- |
| `not_found` | 没有 |
| `no_pbc_list` | 没有 |
| `no_pending` | 没有 |
| `processing` | 有 |

前端如果无条件读 `res.task_id` 去轮询, 前三种会拼出 `/api/files/{pid}/task/undefined`, 直接 404, 然后进度条卡死。

必须先判 `status`, 只有 `processing` 才启动轮询。另外三种各给一句人话提示:

- `not_found` 文件夹不存在
- `no_pbc_list` 还没导入 PBC 清单
- `no_pending` 没有新文件, 用返回的 `files_found` / `skipped` / `missing_detected` 显示

### 3.3 状态过滤用错字段名

`GET /api/pbc/{pid}/list` 后端过滤比对的是 **`status_normalized`**, 不是 `status`。前端如果按 `item.status` 去做前端二次过滤或统计, 结果会和后端不一致。

状态取值只有五个, 注意 `已提供，审核中` 中间是**全角逗号**:

`未提供` / `已提供，审核中` / `已提供` / `不适用` / `待定`

### 3.4 PUT status 漏传 changed_by 会 422

`PUT /api/pbc/{pid}/{item_id}/status` 的 body 是 `StatusUpdateBody{ status: str 必填, changed_by: str 必填, note: str = '' }`。

`changed_by` 漏传直接 422。前端手动改状态时传 `changed_by: 'manual'`。

后端只认这四个值: `watchdog` / `ai-auto` / `manual` / `drag-drop`。

### 3.5 变更面板有两套实现在打架

- `index.html` 里有原生弹窗, state 是 `changePanel: {show, loading, items, filter, error, unread}`, 方法 `openChangePanel` / `loadChangeLog` / `computeChangeUnread` / `markChangesSeen`
- `pbc-enhance.js` 模块三又重做了一个右侧全高侧栏 `.pbcg-vh`, 在捕获阶段劫持所有文本含 文件变更 的 button, `e.preventDefault(); e.stopPropagation();` 并强制把 `d.changePanel.show` 设成 false

两套同时在, 点按钮的行为取决于加载顺序, 表现为点了没反应或者闪一下就关。**二选一, 建议移除 pbc-enhance.js 的模块三**, 保留 index.html 原生实现。

### 3.6 change-log 响应字段是 logs 不是 items

`GET /api/files/{pid}/change-log` 返回:

```json
{ "project_id": "demo", "count": 12, "logs": [ ... ] }
```

顶层是 **`logs`**。前端如果读 `res.items` 拿到 undefined, 面板永远空。

每条 log 的字段: `change_type` / `file_name` / `changed_by` / `changed_at` / `detail`。

`change_type` 取值: `added` / `archived` / `reclassified` / `approved` / `missing` / `deleted`。

### 3.7 首屏 Promise.all 一个失败带崩全部

首屏是:

```js
const [list, dash, heat, brief, rt, fc, pc, cl] = await Promise.all([ ... ])
```

`Promise.all` 只要有一个 reject, 整个首屏就挂。目前只有 `API.changeLog(...)` 挂了 `.catch(() => null)`, 其他兄弟 promise 要么全部补 `.catch`, 要么换 `Promise.allSettled`。

变更日志本身不是首屏必需, 建议把 `API.changeLog` 从首屏移出去, 改成打开面板时懒加载。

### 3.8 中文字符被吞

以下几处字符串在编辑过程中丢字了, 照下面改回去:

| 现状 | 应为 |
| --- | --- |
| `'后  正在异步创建 demo 项目，请稍候刷新'` | `'稍后正在异步创建 demo 项目，请稍候刷新'` |
| `'导出当前 PBC 清单  含已回写状态和文件路径）'` | `'导出当前 PBC 清单（含已回写状态和文件路径）'` |
| `else if(st==='不   用') g.na++;` | `else if(st==='不适用') g.na++;` |
| `x-text="'已提供或审核中 '+progressProvided+'，   '+progressTotal"` | `x-text="'已提供或审核中 '+progressProvided+'，共 '+progressTotal"` |

### 3.9 两个历史隐患

- **P2-15** `cdn.tailwindcss.com` 和 `cdn.jsdelivr.net/npm/alpinejs` 都没有 fallback, 任一不可用则整个前端白屏。`smoke_frontend.py` 的第 2 项用例专门盯这个
- **P2-16** `localStorage` 的 `pbc_onboarded` / `pbc_last_project` 没有过期机制, 指向已删项目时静默 fallback, 表现为打开就是空白项目
