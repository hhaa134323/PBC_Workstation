# 诊断：点细条展开后，大卡片不出现

结论写在前面：**不是 Alpine 响应式的问题，也不是 `briefingDelta` 赋值时机的问题。**
是 `pbc-enhance.js` 模块一还在运行，它给 `#briefing-card` 加了 `pbcg-brief-off` 这个 class，而这个 class 在 CSS 里是 `display:none !important`，直接盖掉了 Alpine `x-show` 写的行内 display。

注释里写了已废弃，但代码没删，IIFE 照常执行。

## 证据链

`app/static/pbc-enhance.css` 第 9 行：

```css
/* 收起时隐掉大卡片。用 important 盖过 Alpine 的行内 display */
.pbcg-brief-off{display:none !important}
```

注释本身就说明了它的设计目的就是压过 Alpine。

`app/static/pbc-enhance.js` 模块一，`boot()` 仍在跑：

```js
function boot() {
  var timer = setInterval(function () {
    var found = findCard();          // document.getElementById('briefing-card')
    if (found) {
      card = found;
      addFoldBtn();
      makeBar();
      folded = loadFoldState();      // 默认 true
      if (folded) setFold(true);     // 在这里加上了 pbcg-brief-off
      watchCard();
      watchTabs();
      setInterval(function(){ sync(); }, 2000);
      ...
```

`setFold(true)` 干的事：

```js
card.classList.add('pbcg-brief-off');
makeBar();
paintBar();
bar.style.display = hasPbc ? 'flex' : 'none';
```

## 实际发生的顺序

1. 页面加载，Alpine 起来，`briefFolded = true`，Alpine 的细条显示，Alpine 的大卡片 x-show 为 false
2. `pbc-enhance.js` 的 `boot()` 轮询命中 `#briefing-card`，执行 `setFold(true)`，给卡片加上 `pbcg-brief-off`
3. 用户点 Alpine 的细条，`toggleBriefFold()` 把 `briefFolded` 改成 false
4. Alpine 响应式正常工作了，细条隐藏，大卡片的行内 `display:none` 被移除
5. 但 `pbcg-brief-off` 还挂在卡片上，`display:none !important` 生效，卡片依旧不可见
6. 结果就是细条没了，大卡片也没有

第 4 步是对的，所以往 Alpine 那边查会一直查不到东西。

## 还有三个连带问题

**二、多插了一条旧细条。**
`makeBar()` 创建 `.pbcg-brief-bar` 并 `insertBefore` 到卡片前面。它和 Alpine 新写的细条是两个独立元素，各有各的显隐逻辑。现在没看到重复，是因为两者恰好一隐一显，隐患一直在。

**三、两个定时器会把状态改回去。**

```js
setInterval(function(){ sync(); }, 2000);   // 每 2 秒按 folded 变量重画细条
setInterval(function() {                    // 每 1 秒检测项目切换
  var newPid = getPid();
  if (newPid && newPid !== oldPid) {
    folded = loadFoldState();
    if (folded) setFold(true);              // 又加回 pbcg-brief-off
  }
}, 1000);
```

模块一内部的 `folded` 和 Alpine 的 `briefFolded` 是两套状态，互不知道对方。项目切换那个定时器第一次跑的时候 `oldPid` 是空字符串，必定触发一次 `setFold(true)`。另外 `watchTabs()` 监听所有 `nav.tabs .tab` 点击，120ms 后强制收起。

**四、两套 localStorage key 打架。**
模块一用 `pbc_brief_folded_{pid}` 和 `pbc_brief_seen_{pid}`，Alpine 那边是另一套 key。刷新后两边可能读出不一样的值。验收第 4 条失败很可能就是这个。

## 修法

### 第一步，删掉模块一的 JS

`app/static/pbc-enhance.js` 从文件开头的注释块起，到模块一那个 IIFE 的 `})();` 为止，整段删掉。边界很清楚：

- 起点：文件第一行那个注释块，里面写着模块一：今日简报收起
- 终点：`if (document.readyState === 'loading') { document.addEventListener('DOMContentLoaded', boot); } else { boot(); } })();` 之后紧接着就是模块二顶栏按钮统一的注释块

随之删掉的函数，模块二模块三都不引用：
`getPid` `loadFoldState` `saveFoldState` `getLastSeen` `saveLastSeen` `esc` `root` `findCard` `hasData` `counts` `makeBar` `paintBar` `addFoldBtn` `setFold` `sync` `watchCard` `watchTabs` `boot`

注意模块二模块三里各自有同名的 `root()`，它们在自己的 IIFE 作用域内，不受影响。

### 第二步，删掉模块一的 CSS

`app/static/pbc-enhance.css` 从第 9 行 `.pbcg-brief-off` 起，到 `@media (max-width:640px){ .pbcg-brief-bar .pbcg-bb-txt{display:none} }` 为止，整段删掉。涉及的选择器：

```
.pbcg-brief-off
.pbcg-brief-bar          及 :hover
.pbcg-bb-dot             及 .calm
.pbcg-bb-name
.pbcg-bb-txt             及内部 b
.pbcg-bb-act             及 svg
.pbcg-bb-meta
.pbcg-brief-bar.alert    及内部 .pbcg-bb-dot
@keyframes pulse
.pbcg-brief-fold         及 :hover 和 svg
@media (max-width:640px) 里 .pbcg-bb-txt 那条
```

`@keyframes pulse` 删之前先确认全库没有别处引用。

### 第三步，清掉旧的 localStorage key

在 Alpine 的 init 里对 `pbc_brief_folded_{pid}` 和 `pbc_brief_seen_{pid}` 做一次性迁移或直接 `removeItem`，避免本地残留状态干扰。

### 第四步，验证

改完硬刷新 Ctrl+Shift+R，在 Console 里跑：

```js
document.getElementById('briefing-card').className
// 不应该再出现 pbcg-brief-off

document.querySelectorAll('.pbcg-brief-bar').length   // 应该是 0
document.querySelectorAll('.pbcg-brief-fold').length  // 应该是 0
```

然后过四条验收：默认收起显示细条、点细条展开显示增量事件、点收起回到细条、刷新后保持折叠状态。第 3 条和第 4 条之前没验证通过，大概率是同一个原因的连带失败，删完应该一起好。

## 如果删完还是不显示

那时候才轮到查 Alpine。按这个顺序：

1. `Alpine.$data(document.querySelector('[x-data]')).briefingDelta` 看有没有值
2. `getComputedStyle(document.getElementById('briefing-card')).display` 看最终计算值
3. 如果 display 是 none 但 Alpine 状态正确，用 devtools 的 Computed 面板看是哪条 CSS 规则赢了

`x-show` 的条件 `!loading && briefingDelta && !briefFolded` 本身没问题，`x-show` 会在依赖变化时自动重新求值，不需要手动触发。唯一要注意的是 `briefingDelta` 赋值时做整体替换 `this.briefingDelta = data`，不要逐个改属性。

## 顺带一提

前端审计说明 3.5 已经提过模块三和 index.html 原生变更面板两套实现打架。模块一这次是同一类问题：运行时 hook 和组件内状态并存，两边都以为自己说了算。建议 `pbc-enhance.js` 逐步退役，功能收回 index.html 由 Alpine 统一管。
